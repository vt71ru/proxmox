Firewall.md
Политика сетевой безопасности домашней инфраструктуры

Версия: 2.0
Статус: Сводная техническая документация
Платформа: Proxmox VE 9.0
Маршрутизатор: GL.iNet Flint 2 (OpenWrt)
Коммутатор: TP-Link SG3210
Основной Firewall: OpenWrt Firewall 4 (nftables)

1. Цель

Обеспечить контролируемую сетевую безопасность домашней инфраструктуры.

Основные задачи:

Защита внутренних сетей от несанкционированного доступа из интернета.
Контроль межсетевого взаимодействия между VLAN.
Изоляция гостевых и IoT-устройств.
Сохранение административного доступа к Proxmox.
Контроль доступа к NAS.
Обеспечение работы DLNA, SSDP и mDNS.
Сохранение доступа к Nginx, Git и PostgreSQL.
Контроль VPN-подключений.
Исключение неизвестных механизмов удалённого управления.
Сохранение работоспособности существующей инфраструктуры.

Основной принцип:

Запрещено по умолчанию. Разрешено только необходимое и согласованное взаимодействие.

4. Текущая конфигурация Flint 2

На основании предоставленного uci show firewall подтверждены следующие настройки.

4.1. Политика по умолчанию
Параметр	Значение
Input	REJECT
Output	ACCEPT
Forward	REJECT
SYN flood protection	Включена

Это означает:

Неизвестные входящие подключения к маршрутизатору запрещаются.
Неизвестная маршрутизация между зонами запрещается.
Исходящие соединения самого маршрутизатора разрешены.
4.2. Подтверждённые Firewall zones
Зона	Сеть	Input	Output	Forward
lan	LAN	ACCEPT	ACCEPT	ACCEPT
wan	WAN / WAN6	REJECT	ACCEPT	DROP
wg	WireGuard	ACCEPT	ACCEPT	REJECT
servers	VLAN 30	REJECT	ACCEPT	REJECT
workstations	VLAN 20	REJECT	ACCEPT	REJECT
mgmt	VLAN 10	ACCEPT	ACCEPT	REJECT

Важно: настройки Input и Forward — разные механизмы. Разрешённый доступ к самому маршрутизатору не означает разрешение маршрутизации в другие VLAN.

5. Административный доступ
5.1. Proxmox

Подтверждённые адреса:

Основной: 192.168.1.221.
Management: 192.168.10.221.

Веб-интерфейс:

Параметр	Значение
Протокол	HTTPS
Порт	TCP 8006
Назначение	Управление Proxmox

Требования:

Доступ к TCP 8006 только с административных устройств.
Не публиковать порт 8006 в интернет.
Не разрешать управление Proxmox из гостевой сети.

Текущее правило Flint 2 разрешает доступ из зоны WORKSTATIONS к 192.168.10.221:8006.

Однако в предоставленной конфигурации нет ограничения src_ip для этого правила.

Рекомендуемая целевая политика — ограничить источник адресом Windows 11 192.168.20.132 после проверки маршрутизации и второго интерфейса компьютера.

8. NAS и мультимедийная инфраструктура
8.1. Общая политика

NAS является центральным хранилищем.

Доступ к нему должен быть предоставлен:

Windows 11.
Телефону.
Smart TV.
TV Box.
Разрешённым серверным приложениям.

Адрес NAS и окончательный VLAN пока не подтверждены.

В SG3210 создан VLAN 60 с именем NAS, однако интерфейс маршрутизации VLAN 60 на Flint 2 не предоставлен.

Поэтому перенос NAS в VLAN 60 пока не выполнять.

8.2. SMB
Источник	Назначение	Порт	Политика
Windows 11	NAS	TCP 445	Разрешить
TV Box	NAS	TCP 445	При необходимости
Телефон	NAS	TCP 445	При необходимости
Smart TV	NAS	TCP 445	Только при поддержке
Guest	NAS	TCP 445	Запретить
Интернет	NAS	TCP 445	Запретить

SMB не публиковать через WAN.

Использовать индивидуальные учётные записи и минимальные права на общие каталоги.

8.3. DLNA

DLNA использует SSDP для обнаружения устройств, а HTTP и другие соединения — для передачи контента.

Требуется:

Разрешить SSDP между согласованными сегментами.
Разрешить HTTP-порт медиасервера.
Определить дополнительные порты по фактической реализации NAS.
Обеспечить обратный трафик.
Не разрешать доступ к DLNA из гостевого сегмента.
Не публиковать DLNA в интернет.

Нельзя ограничивать DLNA только UDP 1900.

9. SSDP

Параметры:

Параметр	Значение
Протокол	UDP
Порт	1900
Multicast	239.255.255.250

SSDP обеспечивает обнаружение UPnP/DLNA.

9.1. Политика

Если NAS и клиент находятся в одном VLAN, relay обычно не требуется.

Если устройства находятся в разных VLAN, необходимо отдельное решение для распространения SSDP.

Возможные варианты:

SSDP relay.
Размещение устройств в одном медиасегменте.
Другой совместимый механизм обнаружения.
9.2. Ограничения
SSDP не публиковать в WAN.
Не распространять объявления в Guest.
Не включать relay между всеми VLAN.
Разрешать только согласованные направления.
Учитывать обратные ответы и HTTP-потоки.
10. mDNS

Параметры:

Параметр	Значение
Протокол	UDP
Порт	5353
Multicast	224.0.0.251

mDNS используется для обнаружения совместимых сервисов, включая некоторые реализации AirPlay и Chromecast.

Требования:

Не смешивать mDNS и SSDP.
При необходимости использовать mDNS reflector.
Ограничить reflector необходимыми VLAN.
Не распространять объявления в Guest.
Не публиковать mDNS в интернет.

Reflector устанавливать только после определения реальной потребности.

11. DNS, DHCP и NTP
Служба	Протокол	Порт	Назначение
DNS	UDP/TCP	53	Разрешение имён
DHCP Server	UDP	67	Выдача адресов
DHCP Client	UDP	68	Получение адресов
NTP	UDP	123	Синхронизация времени

Требования:

Каждый VLAN использует согласованный DHCP-сервер.
Клиенты используют разрешённый DNS.
DNS не должен быть открыт для произвольного доступа из WAN.
NTP должен быть доступен внутренним устройствам.
Не создавать второй DHCP-сервер на MikroTik.
Проверить работу DNS и DHCP для каждой сети.
12. VPN и удалённый доступ
12.1. WireGuard

По конфигурации Flint 2 подтверждено:

Параметр	Значение
Интерфейс	wg0
Подсеть	10.250.0.0/24
Адрес маршрутизатора	10.250.0.1
UDP-порт	51820
Peer	Emergency Phone
Адрес peer	10.250.0.2/32

WireGuard уже настроен.

Не удалять существующий peer и не менять ключи без согласования.

12.2. Политика VPN
Проверить актуальность всех peer.
Удалить только подтверждённо ненужные peer.
Проверить AllowedIPs.
Проверить маршрутизацию VPN.
Ограничить доступ VPN к внутренним VLAN.
Не предоставлять VPN полный доступ ко всей инфраструктуре автоматически.
Не публиковать административные службы через WAN.

В текущей конфигурации зона wg имеет Input ACCEPT, Output ACCEPT и Forward REJECT.

Необходимо отдельно проверить доступ VPN-клиента к самому маршрутизатору и отсутствие ненужного доступа к другим сегментам.

16. Proxmox Firewall

Flint 2 контролирует трафик между VLAN.

Proxmox Firewall дополнительно защищает сам гипервизор и виртуальные машины.

16.1. Общая политика
Не открывать управление Proxmox всему LAN без необходимости.
Не открывать TCP 8006 в интернет.
Ограничить SSH.
Не разрешать неиспользуемые входящие соединения.
Сохранить необходимые подключения виртуальных машин.
Не включать строгие правила до проверки bridge и VLAN-aware.
16.2. Правила доступа к гипервизору
Источник	Назначение	Порт
Административный Windows	Proxmox	TCP 8006
Административный Windows	Proxmox SSH	TCP 22 при необходимости
Guest	Proxmox	Запретить
HOME-IOT	Proxmox	Запретить
WAN	Proxmox	Запретить

Основной адрес 192.168.1.221 и Management 192.168.10.221 должны сохраняться.

Перед включением Proxmox Firewall проверить, не блокирует ли он управление через vmbr0 и vmbr0.10.

Требования:

Проверить наличие сертификата.
Проверить отсутствие ненужных перенаправлений.
Не публиковать SMB, PostgreSQL, Proxmox и SSH без отдельного обоснования.
Проверять правила DNAT после каждого изменения.

24. Итоговая политика безопасности
Flint 2 — основной межсетевой Firewall.
SG3210 — VLAN-коммутация.
Proxmox — дополнительный уровень защиты серверов.
NAS — отдельный контролируемый ресурс.
Windows 11 — административная рабочая станция.
HOME и HOME-IOT получают только необходимые разрешения.
Guest не имеет доступа к внутренней инфраструктуре.
PostgreSQL не публикуется в интернет.
Proxmox не публикуется в интернет.
SMB не публикуется в интернет.
SSDP и mDNS не распространяются бесконтрольно.
WireGuard сохраняется после проверки актуальности подключений.
Неизвестные VLAN не создаются автоматически.
Все изменения выполняются после резервирования и проверки.

Главное правило: безопасность не должна достигаться ценой потери управления маршрутизатором, коммутатором или Proxmox. Любое изменение Firewall сначала проверяется на соответствие существующей конфигурации и только затем внедряется.
