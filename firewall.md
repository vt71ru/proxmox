Firewall.md
Политика сетевой безопасности

Версия: 1.0
Статус: Проект согласования
Платформа: Proxmox VE 9.0

1. Цель

Обеспечить контролируемый доступ между сетевыми сегментами, серверами, NAS и домашними мультимедийными устройствами.

Основные требования:

Запрет несанкционированного доступа извне.
Изоляция гостевых устройств.
Сохранение административного доступа.
Работа DLNA и SSDP.
Контролируемый доступ к NAS.
Отсутствие неизвестных удалённых подключений.

3. Базовая политика
Входящие соединения извне запрещены, кроме явно утверждённых.
Управление Proxmox разрешено только доверенным административным устройствам.
Межсетевой доступ разрешается по принципу минимально необходимых прав.
Ответы на установленные соединения разрешаются.
Неизвестные подключения между сегментами запрещаются после проверки существующих зависимостей.
Неизвестные VPN и механизмы удалённого управления не допускаются.

Для DLNA необходимо учитывать дополнительные HTTP-порты медиасервера и динамические порты.

6. SSDP и DLNA

Требуется:

Разрешить SSDP в необходимых сегментах.
Предусмотреть SSDP relay между VLAN, если устройства находятся в разных подсетях.
Не открывать UDP 1900 всему интернету.
Ограничить взаимодействие конкретными мультимедийными сегментами.
Проверить обратные соединения к медиасерверу.
7. mDNS

Для совместимых устройств:

UDP 5353.
Multicast 224.0.0.251.
mDNS reflector только между согласованными VLAN.
Не распространять объявления устройств в гостевой сегмент.
8. Защита административного доступа

Проверить:

Пользователей Proxmox.
API tokens.
SSH authorized_keys.
VPN-подключения.
NAT и Port Forwarding.
Firewall маршрутизатора.
Firewall Proxmox.
Неизвестные службы удалённого доступа.

После передачи системы владельцу отозвать временные учётные записи исполнителя и сменить выданные ему пароли и ключи.

10. Условия приёмки
Proxmox доступен администратору.
Nginx, Git и PostgreSQL работают.
NAS доступен разрешённым клиентам.
Телефон обнаруживает медиасервер.
Телевизор и TV Box воспроизводят видео.
SSDP работает между необходимыми сегментами.
Гостевой сегмент изолирован.
Неизвестные внешние подключения отсутствуют.
Резервная копия Firewall сохранена.
11. Правило безопасности

Не применять правила из этого документа вслепую. Перед внедрением сопоставить их с действующими правилами маршрутизатора, Proxmox и коммутатора.
