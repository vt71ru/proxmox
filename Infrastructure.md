Infrastructure.md
Домашняя сеть и инфраструктура Proxmox

Версия: 2.0
Дата: 3 ноября 2026 г.
Статус: Сводная техническая документация
Основа: Предоставленные конфигурации Proxmox, OpenWrt и результаты диагностики.

1. Цели проекта

Создать стабильную домашнюю инфраструктуру на основе:

OpenWrt — маршрутизация, DHCP, DNS и межсетевое взаимодействие.
Proxmox VE — виртуализация и серверные сервисы.
Управляемого коммутатора — коммутация VLAN.
NAS — хранение данных и медиатеки.
Wi-Fi точки доступа — подключение беспроводных устройств.
Windows 11 — административная рабочая станция.

Обязательные функции:

Сегментация сети посредством VLAN.
Управление Proxmox из Windows 11.
Работа NAS и сетевых папок.
Доступ телевизора и TV Box к медиатеке.
DLNA между телефоном, NAS и телевизором.
SSDP для обнаружения устройств.
mDNS для совместимых сервисов AirPlay и Chromecast.
Контролируемая маршрутизация между сегментами.
Firewall с сохранением действующей связности.
Резервное копирование инфраструктуры.
Возможность восстановления после неудачных изменений.

Главный принцип: не перестраивать работающую сеть с нуля. Сначала фиксировать фактическое состояние, затем согласовывать и выполнять изменения.

Физические интерфейсы LAN: lan1, lan2, lan3, lan4, lan5.
WAN: eth1.
VPN-интерфейс: wg0.

cat /sys/class/net/br-lan/bridge/vlan_filtering

5.2. Сетевой bridge

Подтверждённая конфигурация:

text
auto lo
iface lo inet loopback

iface nic0 inet manual

auto vmbr0
iface vmbr0 inet static
    address 192.168.1.221/24
    gateway 192.168.1.1
    bridge-ports nic0
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes
    bridge-vids 2-4094

auto vmbr0.10
iface vmbr0.10 inet static
    address 192.168.10.221/24


Bridge VLAN-aware включён.

Разрешённый диапазон VLAN: 2–4094.

Не менять адреса, bridge и основной шлюз без предварительного резервирования и проверки удалённого доступа.

10. SSDP, mDNS и Multicast
10.1. SSDP

Параметры:

UDP 1900.
Multicast: 239.255.255.250.

SSDP используется для обнаружения UPnP/DLNA-устройств.

Если телефон, NAS и телевизор находятся в разных VLAN, стандартная маршрутизация не обеспечивает автоматического обнаружения.

Необходимо предусмотреть совместимый SSDP relay.

Требования:

Только необходимые VLAN.
Запрет публикации SSDP в интернет.
Запрет распространения в Guest.
Контроль запросов и ответов.
Проверка последующего HTTP-соединения с медиасервером.

SSDP relay не заменяет правила firewall для передачи медиаданных.

10.2. mDNS

Параметры:

UDP 5353.
Multicast: 224.0.0.251.

Используется для обнаружения совместимых сервисов, включая некоторые реализации AirPlay и Chromecast.

При необходимости использовать mDNS reflector между согласованными VLAN.

Не распространять mDNS в гостевой сегмент без отдельного решения.

10.3. IGMP

Предусмотреть:

IGMP snooping на управляемом коммутаторе при поддержке.
Корректную обработку multicast.
Проверку multicast на Wi-Fi AP.
Проверку взаимодействия проводных и беспроводных клиентов.
Отсутствие ненужного распространения multicast.

SSDP, mDNS и IGMP являются разными механизмами.

11. Firewall и безопасность

Основная политика:

Неизвестные входящие соединения из интернета запрещены.
Административный доступ разрешён только доверенным устройствам.
Межсетевые соединения разрешаются по необходимости.
Ответы на установленные соединения допускаются.
Гостевые устройства изолированы от внутренних сетей.
Неизвестные VPN и механизмы удалённого управления подлежат аудиту.
Правила Proxmox и OpenWrt проверяются совместно.

17. Правила эксплуатации
Не переустанавливать работающие системы без необходимости.
Не менять действующие IP без согласования.
Не удалять существующие Firewall-разрешения без проверки.
Не отключать DHCP до подготовки альтернативы.
Не менять VLAN активного порта без плана отката.
Перед изменениями сохранять конфигурации.
После каждого изменения выполнять только относящиеся к нему контрольные проверки.
Не повторять диагностику уже подтверждённых параметров без причины.
Не создавать неизвестные VLAN автоматически.
Не изменять рабочую маршрутизацию без проверки Windows и OpenWrt.
Не выполнять несколько крупных изменений одновременно.
При потере административного доступа прекращать дальнейшие изменения и восстанавливать предыдущую конфигурацию.

19. Главные решения проекта
OpenWrt остаётся основным маршрутизатором.
Существующая маршрутизация сохраняется.
Proxmox остаётся основой виртуальной инфраструктуры.
VLAN 30 сохраняет назначение серверного сегмента.
VLAN 1, 10, 20, 30 и 40 существуют в текущей конфигурации OpenWrt.
Windows 11 сохраняет два существующих Ethernet-подключения до завершения аудита маршрутизации.
NAS обеспечивает хранение данных и медиатеку.
Smart TV подключается через Wi-Fi.
Телефон должен обнаруживать NAS и совместимые устройства.
TV Box должен иметь доступ к медиатеке.
SSDP необходим для DLNA discovery между согласованными сегментами.
mDNS применяется только там, где он действительно необходим.
Firewall согласуется с действующей конфигурацией.
Неизвестные VLAN не создаются автоматически.
Любые изменения выполняются с резервированием и планом отката.
